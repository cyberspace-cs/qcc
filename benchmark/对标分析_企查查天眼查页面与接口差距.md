## 二、前端学习要点（我们该抄什么）

### 2.1 信息架构

| 设计点 | 两家的做法 | 我们的演示系统 |
| --- | --- | --- |
| 查询三支柱 | 查公司 / **查老板** / **查关系** 三 Tab 平级 | 只有查公司 ❌ |
| 快捷功能宫格 | 10~12 个垂直场景入口（批量查询、地图、核名、融资…） | 4 个能力卡片 ❌ |
| 内容池 | 商业快讯 + 早晚报 + 天眼实时（分钟级资讯流） | 无 ❌ |
| 右侧悬浮栏 | 小程序/APP/公众号/客服/反馈 常驻 | 无 ❌ |
| 会员转化 | 价格表 + 权益对比 + 登录弹窗盖层 | 无 ❌ |

### 2.2 视觉与交互

1. **主色**：两家都是品牌蓝（天眼查 #2B6BD4 系、企查查 #0A66FF 系）+ **橙色主 CTA 按钮**（"天眼一下"/"查一下"）——蓝底橙钮对比强烈，我们目前蓝底蓝钮，CTA 不够突出。
2. **搜索框**：Tab 切换查询类型（同一输入框复用），占位符带示例，右侧附扫码/高级搜索；热搜词以小胶囊排在框下方。
3. **风险可视化**：企业详情页用**红/橙/绿角标 + 数字计数**直接标风险条数（诉讼 N / 失信 N / 被执行 N），红色优先吸引视线；已注销/吊销企业名称旁挂灰色/红色状态签。
4. **权益对比表**：`只看不同` 开关（qcc_vip.png 右上角），三档会员逐行打勾。
5. **登录墙**：所有数据页 302 到 `/login?from=原路径`，登录后回跳——我们做权限体系时应保留此交互。

## 三、后端接口差距清单（核心结论）

我们演示系统现有 6 个接口：`/api/search`、`/api/company/{id}`、`/api/graph/{id}`、`/api/hot`、`/api/stats`、`/api/admin/change/{id}`。
对标两家开放平台（天眼查 200+、企查查 100+），按优先级列出缺口：

### P0 —— 核心闭环缺失（不做就不是同类产品）

| 缺口 | 对标接口 | 建议接口 | 涉及存储 |
| --- | --- | --- | --- |
| **查老板（人物维度）** | 人员所有公司（¥6/次，最贵=最难）、人员所有角色 | `GET /api/person/{pid}/companies`、`/roles` | 图库 Person 节点反向边 |
| **查关系（多主体）** | 最短路径发现 | `GET /api/graph/path?from={cid1}&to={cid2}` | Nebula GO 语句，Redis 缓存 `qcc:graph:path:*` |
| **历史沿革** | 历史股东 / 历史主要人员 / 历史对外投资 / 历史工商 | `GET /api/company/{id}/history?type=holder\|staff\|invest` | MySQL `*_history` 影子表 |
| **变更记录** | 变更记录 / 公司公示-股权变更 | `GET /api/company/{id}/changes` | `company_change_log` 表（现在只有事件流无落库） |
| **失信/被执行/限高 单列** | 失信核查 / 被执行人核查 / 限高核查（三家分立，各 ¥0.3/次） | `GET /api/company/{id}/risks?type=dishonest\|zhixing\|xianxiao` | 拆细 `company_lawsuit` 为多张风险表 |
| **用户体系** | 登录/注册/VIP 套餐 | `POST /api/auth/login`、`GET /api/member/plans`、`POST /api/member/subscribe` | `user`、`member_plan`、订单表 |

### P1 —— 商业化与数据纵深

| 缺口 | 对标 | 建议接口 |
| --- | --- | --- |
| 企业年报 | 企业年报（¥1/次） | `GET /api/company/{id}/annual-reports` |
| 行政许可/资质证书 | 资质证书（¥0.3/次） | `GET /api/company/{id}/licenses` |
| 招投标 | 招投标查询 | `GET /api/company/{id}/biddings` + 垂直搜索 `POST /api/bidding/search` |
| 融资历史 | 投融资数据库 | `GET /api/company/{id}/financings` |
| 上市公司财务三表 | 利润表/资产负债表/现金流量表 | `GET /api/company/{id}/financials` |
| 股权出质/动产抵押/对外担保 | 经营风险域（28+ 接口） | `GET /api/company/{id}/pledges`、`/mortgages`、`/guarantees` |
| 新闻舆情（打情绪标签） | 新闻舆情（¥0.15/次） | `GET /api/company/{id}/news?sentiment=neg` |
| 企业核名/批量查询/高级筛选 | 高级搜索、批量查询 | `POST /api/search/advanced`、`POST /api/search/batch` |

### P2 —— 增值与开放生态

| 缺口 | 对标 | 说明 |
| --- | --- | --- |
| 企业信用报告（聚合导出） | 基础版/专业版信用报告 | 聚合 P0/P1 数据一键生成 PDF，按份计费 |
| 开放 API 网关 | ApiCode 体系 / Bearer Token | 我们只有内部接口；需 API Key 签发、按次计费、`qcc:api:quota:{uid}:{date}` 落地成真 |
| 三要素核验 | 企业三要素验证（¥0.1/次） | 企业名+税号+法人名一致性校验（高频低价引流品） |
| MCP/AI Agent 接入 | 企查查 67 工具 MCP、天眼 AI | 把核心查询封装为 MCP tools，是新趋势 |
| 监控雷达增强 | 天眼实时、动态监控 | 我们有推送雏形，缺：监控维度配置、推送渠道管理、监控分组 |
| 数据大屏/地图 | 天眼地图、千寻地图 | `GET /api/map/companies?bbox=...` 按地理围栏聚合 |

## 四、给三件套文档的回填建议

1. **SRS**：新增功能需求 `F-09 查老板（人物画像）`、`F-10 查关系（多主体路径）`、`F-11 历史沿革`、`F-12 会员与订单体系`；非功能补充"未登录访问数据页强制跳登录"。
2. **HLD**：微服务拆分增加 **人物画像服务**（人员-任职-风险聚合）与 **资讯内容服务**（商业快讯/早晚报，SEO 内容池）；新增开放 API 网关的计费链路图。
3. **LLD**：新增表：`company_change_log`（变更记录落库）、`person_info`（自然人主档）、`company_history_*`（历史影子表）、`member_order`（订单）、`news_feed`（资讯）；Redis 增加 `qcc:graph:path:*`（已预留）与 `qcc:person:companies:{pid}`。
4. **前端**：搜索框改三 Tab（查企业/查老板/查关系），主 CTA 改橙色，企业详情加风险角标计数，新增 VIP 价格对比页。
